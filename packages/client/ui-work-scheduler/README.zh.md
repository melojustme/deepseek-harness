# @deepseek-ai/dsh-client-ui-work-scheduler

[English](README.md) | 中文

原生工作调度面板通过 Client 插槽注册侧栏入口与模态窗口，默认提供个人规划看板，并可选打开执行／审查列，同时提供任务详情、执行历史和人工审查。[本地执行提供者](../../work-scheduler/work-scheduler-execution-local/README.zh.md)独立于面板可见状态管理执行。

## 规划与执行

选择工作区并创建任务，填写描述即可；验收条件可选，每行一项。默认**规划看板**展示待办、用户命名的线程列、已暂停和已完成。可用「新建任务」或列内「添加」创建；卡片上可编辑、删除（删除需确认）。尚未执行的卡片可在这些列之间移动，包括勾选完成，无需 Host 执行证据。看板选项提供可选的**执行看板**（待办／进行中／待审查／已通过）供 SOP 审查。尚未执行的卡片仍可在该板上勾选完成；已有执行记录的卡片继续受证据约束，拖动不能生成审查证据。创建草稿会话只填入未发送文本；执行任务会创建独立的原生执行 Session。看板区分人工规划完成与审查通过。

执行使用所选 Git 版本，默认为 HEAD，不包含原工作区未提交改动。取消操作等待原生资源释放。Todo 进度和待处理用户交互来自 Session 投影；原生会话入口提供完整日志、审批和问答操作。打开隔离执行会话后仍可返回所选看板。

审查展示固定日志摘要哈希、文件差异、执行摘要、工具结果及保留产物目录。文件变化后需重新固定证据。接受失败工具结果需要填写原因；返工需要反馈，并从上一轮快照创建新的隔离轮次。通过只记录人工决策，不合并或推送。待审查任务占据线程位置，直到通过或显式异步让出；恢复占位保留等待任务的返回位置。

规划看板卡片支持拖放与 Alt 加方向键。尚未执行的任务可在规划列之间移动，包括已完成，且不会创建执行轮次。卡片「编辑」在看板上就地改写；卡片「删除」确认后移除该尚未执行的任务，且不会改写 Host 执行记录。已有执行记录的卡片在规划看板上不可拖动，也不显示这两项卡片操作。在执行看板上，尚未执行的任务可在所属队列中排序且不能越过已有执行记录的任务，并可不带证据地归档。把已有执行记录的卡片移入执行中需确认，移回活动任务需确认停止，移动待审查任务则打开通过或返工详情。文案「先完成执行并检查本轮证据，才能通过审查。」仅在已有执行记录的卡片被拖到已通过且尚无审查证据时出现。审查证据由 Host 生成，通过操作提交明确命令。拖动期间或确认前修订号变化会拒绝旧操作，断线看板不接受编辑。

## 数据与连接状态

不依赖 React 的对象层 `WorkSchedulerRuntime` 管理所选文档、修订号、条件写入和周期刷新。经过校验的 `refreshIntervalMs` 配置决定刷新周期。插槽 store 只保存展示状态。关闭面板不会停止 Host 执行或运行时刷新；卸载插件会释放运行时与两个插槽贡献。

加载、保存或断线时禁用编辑。保存失败保留编辑字段，结果不确定的执行提交保留命令标识用于重试。工作区代次隔离会丢弃迟到响应。导入校验版本 3，拒绝错误引用、重复位置、旧格式及与 Host 不同的执行记录，不修复或丢弃执行证据。导出下载完整版本文档。

「新建任务」和每列的「添加」打开内联编辑器，看板保持可见。「清空看板」先确认，再保存一份版本兼容的空文档，替换当前工作区记录（包括 Host 拥有的执行轮次）；其他工作区不受影响。返回详情前的看板时保留筛选条件，并将焦点交还选中的卡片。看板导入导出、Git 版本和任务安排作为可展开的次级控件。分阶段流程与拖动语义见[交互设计](../../../docs/design/work-scheduler/agent-delivery/interaction.zh.md)。

## 窗口与无障碍

桌面窗口居中显示，支持调整大小和应用内全屏。窄屏使用整个视口，并在选中任务时用详情替换看板。Escape 先关闭最内层编辑器或详情，再关闭窗口。关闭详情后焦点返回任务卡片，Tab 保持在对话框内，执行状态同时提供文字与进度语义。

## 模型体验

### 已记录的任务输入

#### 模型看到什么

面板本身不添加模型输入。显式执行将任务描述、验收条件及返工反馈交给提供者，作为原生 Session 输入记录。参见[提供者的模型体验](../../work-scheduler/work-scheduler-execution-local/README.zh.md)。

#### Token 影响

无直接输入；执行提供者管理任务输入，所选预设管理模型请求。

#### KV Cache 影响

没有直接影响；执行提供者与所选预设管理模型请求。

## 已知限制与延期工作

- 原生执行需要已经注册且存在提交的 Git 仓库。产物保留在本地，后续集成与清理由用户单独执行。
- 规划和执行都需要工作区。导入以条件写入替换规划数据，不能移入其他工作区的执行历史。
- 完整日志与待处理交互在原生 Session 视图打开；面板展示摘要与有界证据。
