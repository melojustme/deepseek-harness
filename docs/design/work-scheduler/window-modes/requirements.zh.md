# 工作调度窗口模式需求

[English](requirements.md) | 中文

## 原始需求

> 工作调度这个弹窗可以适当的缩放，可以有个放大全屏按钮。

“工作调度”弹窗应以合适的窗口尺寸打开，支持缩放，并提供放大至应用视口的控件。

## 需求拆解

### 功能需求

| ID | 需求 |
|---|---|
| FR-01 | 在桌面视口上打开“工作调度”时，默认显示居中窗口，不立即覆盖完整应用视口。 |
| FR-02 | 窗口默认尺寸约为 `92vw` × `86vh`，不超出视口，并支持指针缩放，但不得小于布局可用的最小尺寸。 |
| FR-03 | 标题栏控件在窗口模式和应用全屏模式之间切换。从全屏还原时，窗口恢复放大前的位置和尺寸。 |
| FR-04 | 现有关闭按钮和 `Escape` 会关闭整个“工作调度”弹窗。打开关联会话时，选中该会话后也会关闭整个弹窗。 |
| FR-05 | 关闭后重新打开“工作调度”时，恢复默认窗口尺寸；窗口尺寸和全屏状态均不持久化。 |
| FR-06 | 小视口使用现有响应式内容布局，并以应用全屏弹窗显示，不展示不适用的缩放或放大控件。 |
| FR-07 | 帮助面板在窗口和全屏模式下均限制在“工作调度”窗口内。 |

### 非功能需求

| ID | 需求 |
|---|---|
| NFR-01 | 标题栏控件、表单、泳道、任务卡、检查器和可见文本在支持的视口与窗口尺寸下不得重叠。 |
| NFR-02 | 放大控件具有随模式在 `全屏` 和 `还原` 之间变化的无障碍名称；切换模式时，键盘焦点保持在该控件上。 |
| NFR-03 | 缩放和模式变化只影响展示，不得修改或保存调度文档。 |
| NFR-04 | 设计继续使用现有主题 token 和图标原语，不引入独立的视觉语言。 |

### 约束

- 全屏指填满 dsh 应用视口；该功能不调用浏览器 Fullscreen API，也不隐藏浏览器界面。
- 改动保持在现有 `shell.overlay` 贡献和 Client 自有视图状态内，不新增 Host API、存储字段、会话事件或模型可见输入。
- 点击遮罩层不关闭弹窗，避免意外丢失用户当前的视觉上下文。
- 通过拖动标题栏移动窗口，以及跨打开或浏览器重载持久化窗口几何信息，不属于本次范围。

### 验收标准

| ID | 验收标准 |
|---|---|
| AC-01 | 在 `1564x996` 视口下，“工作调度”打开后窗口周围存在可见留白，四泳道看板仍可用，必要时看板区域可水平滚动。 |
| AC-02 | 拖动缩放控件会改变窗口尺寸，且不会让控件或检查器缩小到受支持的最小布局以下。 |
| AC-03 | 触发 `全屏` 会填满应用视口；触发 `还原` 会恢复之前的窗口位置和尺寸。 |
| AC-04 | 在缩放或全屏切换后关闭弹窗，再次打开时会恢复默认窗口尺寸。 |
| AC-05 | 点击可用的会话关联会选中该会话，并移除“工作调度”弹窗，无需再次关闭。 |
| AC-06 | 在窄视口上，“工作调度”填满应用视口，且不显示放大控件和缩放控件。 |
| AC-07 | 组件测试覆盖模式转换和关闭行为；真实 Web 测试覆盖用户可见的导航和弹窗结果。 |

## 已确认的方案细节

所选方案同时提供自由缩放和窗口／全屏两状态控件。窗口几何信息只是单次打开期间的临时展示状态。桌面窗口模式是默认值；响应式小屏模式等效于全屏。原型对比紧凑、可缩放和最大化三种展示，其中可缩放展示是正式实现候选方案。
