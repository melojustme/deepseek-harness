## 1. 设计概述

### 1.1 背景与目标

“工作调度”当前通过一个填满应用视口的 `shell.overlay` 贡献展示。所选方案保留该扩展点和调度器内容，同时把覆盖视口的模态遮罩层与可改变尺寸的窗口分开。桌面用户可以保留周边应用上下文、使用指针缩放，并显式切换应用全屏，不改变调度数据或会话选择。

### 1.2 范围

| 范围 | 包含 | 不包含 |
|---|---|---|
| 展示 | 桌面窗口几何信息、缩放控件、全屏／还原控件、响应式覆盖和受窗口限制的帮助面板 | 移动窗口、浏览器全屏或其他调度器布局 |
| 状态 | 单次打开期间的临时几何信息和请求显示模式 | 持久化到调度文档、浏览器存储或 Host 存储 |
| 现有交互 | 关闭、`Escape`、会话导航后关闭弹窗 | 修改任务转换、拖放位置、导入／导出或持久化 |

### 1.3 方案选型

| 方案 | 说明 | 取舍 | 决定 |
|---|---|---|---|
| 紧凑固定窗口 | 使用较小的固定弹窗，不提供自由缩放 | 简单，但无法适应不同任务密度 | 仅用于原型对比 |
| 可缩放窗口与全屏控件 | 以窗口模式打开，支持有界指针缩放，并可切换到应用视口 | 需要增加临时几何状态和响应式规则 | 已选择 |
| 始终最大化 | 保留当前填满视口的展示，只增加还原控件 | 保留信息密度，但不能满足默认缩放需求 | 仅用于原型对比 |

所选方案以最小行为改动同时满足自由缩放和单次操作放大需求。现有架构所有者仍是[浏览器插件](../../../../packages/client/ui-work-scheduler/README.zh.md)和其对应的[工作调度器决策](../../../../.agents/notes/implemented/feature/2026-08-18-web-work-scheduler.zh.md)。[一次性原型](../../../../packages/client/ui-work-scheduler/prototype/window-modes.html?variant=resizable)通过 `variant` 查询参数展示全部三个方案，并默认打开已选择的可缩放方案。

## 2. 整体架构

### 2.1 所有权

该功能保持在浏览器插件内。`shell.overlay` slot 继续负责挂载和撤销；插件自有 store 继续拥有持久文档加载状态；弹窗组件拥有显示模式和几何信息，因为这些值在单次挂载视图之外没有意义。

| 部分 | 职责 | 依赖 |
|---|---|---|
| Shell overlay 贡献 | 随插件生命周期挂载和移除“工作调度”模态层 | 现有 slot 注册表 |
| 模态遮罩层 | 覆盖应用、建立模态层叠，并居中默认窗口，且不因点击遮罩而关闭 | 现有主题 token |
| 调度器窗口控制器 | 解析有效模式、限制几何信息、切换全屏／还原，并在关闭时重置展示 | 组件本地状态和视口尺寸 |
| 调度器内容 | 渲染现有标题栏、命令栏、看板、检查器、任务卡和帮助面板 | 现有调度器 store 和 Client 注册表 |
| 会话导航回调 | 在关闭整个弹窗前选中关联会话 | 现有 Client 会话注册表 |

### 2.2 分层

- 模态遮罩层始终填满应用视口，并拥有模态 `dialog` 语义。
- 调度器窗口是遮罩层内有界的可见容器。
- 标题栏控件修改窗口展示或关闭模态层，不修改调度数据。
- 看板和检查器保留当前的滚动所有权，因此较小窗口只会改变可用空间，不会改变文档结构。

无需架构图：所有权表和四层列表已完整表达关系，无需引入独立视觉产物。

## 3. 核心交互设计

### 3.1 显示模式

| 请求模式 | 桌面有效模式 | 小屏有效模式 | 标题栏控件 |
|---|---|---|---|
| 窗口 | 有界可缩放窗口 | 应用全屏 | 桌面端显示 `全屏`；小屏隐藏 |
| 全屏 | 应用全屏 | 应用全屏 | 桌面端显示 `还原`；小屏隐藏 |

小屏行为优先于请求模式。在同一次打开期间，视口重新跨入桌面范围时，之前请求的桌面模式重新生效。

### 3.2 几何信息

| 上下文 | 初始尺寸 | 范围 | 缩放行为 |
|---|---|---|---|
| 桌面窗口 | 约 `92vw` × `86vh`，居中且每一边都保留可见遮罩层 | 不超出应用视口；最小尺寸保留可用的命令栏、看板和检查器 | 使用右下角指针缩放；手势期间左上角保持不变 |
| 桌面全屏 | 填满应用视口 | 精确的视口范围 | 禁用 |
| 小屏 | 填满应用视口 | 精确的视口范围 | 禁用 |

进入全屏前，控制器会记录当前窗口几何信息。还原时使用该几何信息。关闭会清除该信息，因此下次打开使用默认居中尺寸。

### 3.3 状态转换

| 事件 | 前置条件 | 展示结果 | 调度文档影响 |
|---|---|---|---|
| 打开调度器 | 弹窗已关闭 | 桌面端以默认窗口几何信息打开，小屏使用有效全屏 | 仅现有加载行为 |
| 缩放 | 有效模式是桌面窗口 | 把宽度和高度限制在受支持范围内 | 无 |
| 触发 `全屏` | 有效模式是桌面窗口 | 记录窗口几何信息并填满应用视口 | 无 |
| 触发 `还原` | 桌面请求模式为全屏 | 恢复已记录的窗口几何信息 | 无 |
| 触发关闭或按 `Escape` | 弹窗已打开 | 移除完整模态层并清除展示状态 | 现有保存行为保持不变 |
| 打开关联会话 | 关联在当前 Workspace 中可解析 | 选中会话，然后移除完整模态层 | 无 |
| 进入小视口 | 弹窗已打开 | 应用有效全屏并隐藏不适用的窗口控件 | 无 |

### 3.4 标题栏控件

标题栏操作顺序为帮助、导出、导入、全屏／还原和关闭。模式控件使用现有全屏图标，在标签和按下状态变化时保持挂载，并在转换后保留键盘焦点。关闭控件仍是最后一项标题栏操作，并继续关闭整个弹窗。

控件在窗口模式下把 `aria-label` 和 `title` 暴露为 `全屏`，在全屏模式下暴露为 `还原`。弹窗保留 `工作调度` 无障碍名称。小视口省略该控件，而不是显示一个没有可见效果的操作。

### 3.5 缩放行为

指针只能从专用的右下角控件开始缩放。控制器捕获起始指针和窗口尺寸，在移动期间应用有界尺寸，并在手势完成或组件 dispose 时释放文档级监听器。该手势不会移动窗口、修改看板数据或触发持久化。

全屏是需要最大工作区用户的非拖动替代操作。所选范围不增加用键盘任意递增或递减窗口尺寸的功能。

### 3.6 遮罩层与帮助面板

遮罩层在视觉上把模态窗口与下层对话分开，同时让该上下文仍可辨认。点击遮罩层不会关闭弹窗。帮助面板从相对视口固定位置改为相对调度器窗口定位，以避免超出窗口几何范围。

## 4. 数据模型

### 4.1 临时视图状态

| 值 | 含义 | 生命期 |
|---|---|---|
| 请求显示模式 | 用户在窗口和全屏之间的桌面选择 | 单次打开的弹窗实例 |
| 窗口几何信息 | 当前有界宽度和高度，以及还原时使用的锚定左上位置 | 单次打开的弹窗实例 |
| 小屏匹配 | 响应式全屏是否覆盖请求模式 | 从当前视口派生 |

### 4.2 持久数据

版本 2 调度文档不变。窗口尺寸和显示模式是展示首选项，因此不会进入 Workspace 文档、Host 存储、会话日志、导入／导出 JSON、模型上下文或本地化资源。

## 5. 接口

### 5.1 现有接口

| 接口 | 处理 |
|---|---|
| `shell.overlay` 贡献 | 保留为模态遮罩层和调度器窗口的挂载点 |
| 工作调度器 store action | 现有打开、关闭、帮助、文档和持久化 action 保持不变 |
| 会话导航回调 | 保留；成功调用后关闭整个弹窗 |
| Host `workScheduler.load` 和 `workScheduler.save` | 不变 |

### 5.2 新公开接口

无。显示模式、几何信息、缩放处理和响应式匹配均保持为私有展示行为。不新增配置键、RPC 方法、事件或导出服务。

## 6. 失败行为

| 条件 | 要求的行为 |
|---|---|
| 视口变得小于当前几何信息 | 把有效几何信息限制在视口内；适用时由小屏规则优先 |
| 指针缩放在浏览器窗口外结束 | 监听器清理会结束手势，不会留下已安装的全局指针处理器 |
| 组件在缩放期间 dispose | 清理会释放手势监听器；不持久化几何信息 |
| 关联会话不可用 | 保留现有 `会话不可用` 行为；弹窗不导航也不关闭 |
| 调度器加载或保存失败 | 现有只读错误行为与显示模式保持独立 |

展示改动不新增用户可见错误码。系统通过范围约束防止不受支持的几何信息，而不是事后报告。

## 7. 操作日志

全屏和缩放手势是本地展示操作，不记录 Host 操作日志。现有加载和保存诊断保持不变。实现不得为正常缩放或模式变化增加控制台输出。

## 8. 审计日志

不新增审计事件。显示几何信息不会改变调度数据、权限、配置或其他用户的状态。

## 9. 用户权限

该功能不引入权限区分。任何可打开“工作调度”的用户都可以缩放、最大化、还原或关闭其本地弹窗。现有会话关联规则仍是导航可用性的权威判定。

## 10. 国际化

控件标签遵循现有中文工作调度器展示：`全屏` 和 `还原`。无障碍名称、工具提示、测试和文档使用相同术语。该包未使用 Client locale 服务，本次改动也不创建独立本地化机制。

## 11. 测试策略

| 层级 | 证据 |
|---|---|
| 组件行为 | 默认窗口模式、全屏／还原标签和状态、关闭后重置几何信息，以及现有关闭和会话导航行为 |
| 响应式行为 | 小屏全屏覆盖、隐藏缩放／放大控件，以及变宽后恢复请求的桌面模式 |
| 真实 Web 组合 | 从侧边栏打开、可见桌面遮罩层、关联会话导航，以及自动移除完整弹窗 |
| 视觉检查 | 默认桌面、手动缩放桌面、全屏桌面和窄屏移动端截图，并检查重叠与裁切 |

聚焦组件套件仍是最快的行为信号。现有真实 Web 场景继续证明发布组合在弹窗关闭后显示关联对话。

## 12. 交付与回滚

改动只发布到 Client 包和重新生成的 Web 产物。它不需要数据迁移、Host 重启要求或兼容处理。部署使用普通 Web 构建。回滚 Client bundle 会恢复填满视口的展示，不会转换调度文档。

## 13. 安全与无障碍审查

| 关注项 | 决定 |
|---|---|
| 不可信几何信息 | 把指针派生尺寸限制到视口和最小布局范围，且从不从持久输入解析 |
| 全局手势监听器 | 仅在活动缩放期间安装，并在完成和 dispose 时移除 |
| 意外关闭 | 遮罩层点击不关闭；显式关闭、`Escape` 和成功会话导航保留已定义行为 |
| 键盘访问 | 全屏／还原和关闭是普通可聚焦按钮；模式标签在同一控件元素上更新 |
| 文本和控件重叠 | 稳定的标题栏控件、有界窗口尺寸、现有滚动所有权和响应式布局保持分离 |

该改动不涉及文件系统、进程、凭据、网络或新的授权边界。
