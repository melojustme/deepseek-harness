# 工作调度交互设计

[English](interaction.md) | 中文

本参考文档定义基于[执行设计](design.zh.md)的交互改版。打开[交互原型](interaction-prototype.html)可体验任务创建、执行、审查、返工、失败和卡片移动。原型中的执行结果与配置变化均为模拟，不访问模型，也不修改仓库。

## 导航与操作

看板占满内容区。选择任务后，内容区切换为可完整阅读的任务页；返回时恢复看板选择与筛选条件。任务编辑器使用独立页面。Escape 依次关闭编辑器、任务详情和调度窗口。关闭调度窗口不会取消执行。

每个阶段突出一个下一步操作：保存待办、开始执行、处理待答复事项或通过已审查的证据。停止、返工、编辑和线程管理保留为次级操作。导入导出与 Git 版本设置放入有明确名称的折叠区域。缺少工作区时引导使用现有工作区选择器；缺少模型凭据时进入模型设置，完成后返回原任务并保留输入。

## 拖动规则

原型支持自由模拟跨列移动、同列排序、目标区域高亮、插入位置提示和撤销；也可使用 Alt 加方向键。这些展示交互不代表正式产品可以任意改写执行状态。

| 正式产品中的手势 | 必须执行的行为 |
|---|---|
| 调整未执行任务的顺序 | 使用当前修订号保存规划顺序，拒绝过期写入。 |
| 把待办移入执行中 | 验证前置条件并提交执行命令；缺少配置时打开相应配置流程。 |
| 把执行中的任务移回 | 提供停止操作；Host 确认释放前保留执行状态。 |
| 移入待审查 | 只有 Host 完成执行后才能创建审查证据，拖动不能生成证据。 |
| 把待审查移入已通过 | 打开证据审查，并要求明确点击通过。 |
| 把待审查移回修改 | 收集返工意见并提交新的执行轮次。 |
| 调整或移动已通过结果 | 保留历史决定；新增工作使用独立任务或轮次。 |

撤销只用于可逆的规划移动。执行与审查命令不能通过通用撤销控件回滚。排队轮次、有序线程、写入冲突和断线场景都以 Host 的执行接收与占位状态为准。

## 实施顺序

1. 导航与可读性：完整看板、独立编辑与详情、主要操作、折叠高级操作和键盘返回路径。验证任务保存、错误输入保留和返回焦点。
2. 执行：配置引导、实时活动、待答复事项、停止、失败重试和规划拖动。验证真实命令与过期、断线写入。
3. 审查：固定证据、验收核对、通过、返工和对应命令的跨列手势。验证手势不能绕过证据检查或改写已完成历史。

每个增量都需要针对性的组件检查和真实应用组合快照。原型只提供设计证据；原生模型执行需要通过真实提供商单独验证。
