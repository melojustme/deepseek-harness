# 工作调度：任务执行与审查需求

[English](requirements.md) | 中文

状态：提案，尚未实现。本文是产品需求参考；[技术设计](design.zh.md)定义实现职责，[交互原型](../../../../packages/client/ui-work-scheduler/prototype/agent-delivery.html)使用模拟数据展示流程。

## 目标与基线

把 AutoMaker 的“看板 → 执行 → 实时进度 → 审查 → 通过或返工”核心流程接入现有工作调度插件。用户在同一个 Workspace 中描述任务、分派工作、检查产物并决定是否接受结果。

基线是提交 `b14d2218f9` 的[工作调度插件](../../../../packages/client/ui-work-scheduler/README.zh.md)：已有线程排序、同步与异步阻塞、Session 关联、Todo 进度、工作区持久化和窗口模式。参考项目为 [AutoMaker](https://github.com/AutoMaker-Org/automaker/tree/5888d2e)，其看板交互提供产品参考，运行机制使用 Harness 的原生能力。

## 范围

| 本次设计包含 | 本次设计不包含 |
|---|---|
| 任务创建、线程分组、状态看板、筛选、顺序与阻塞 | AutoMaker 的整套 React/Electron 应用嵌入 |
| 显式执行、排队、停止、重试、限流 | 无人值守自动领取全部待办 |
| 专属执行 Session、实时状态、Todo 与日志入口 | 复制 AutoMaker 的提供商登录或模型目录 |
| 结果摘要、检查证据、执行归属的文件差异、人工通过与返工 | GitHub Issue/PR 同步、提交、推送或自动合并 |
| 断线重连、Host 重启恢复、冲突提示 | 独立终端、跨项目调度、通用工作流编辑器 |

Git 工作区为每次执行创建隔离 worktree，以支持可靠的差异归属；非 Git 工作区可以管理待办，但执行按钮说明暂不支持。通过审查只确认结果并保留 worktree，不把修改合入用户当前分支。这个限制必须在执行前和通过后可见。

## 用户流程

1. 在工作调度中创建任务，填写描述、验收条件并选择线程。创建只保存待办，不发送模型请求。已有 Session 关联继续作为上下文入口。
2. 点击“执行任务”。Host 验证任务、Workspace、模型配置、线程前置任务和并发额度；接受后显示排队或执行中，并提供本次执行的 Session 入口。
3. 查看当前步骤、真实 Todo 计数、工具活动及等待用户操作提示。关闭面板不终止执行；只有“停止执行”请求取消。
4. 执行结束进入待审查或失败状态。用户查看本次执行摘要、实际检查记录和固定版本的文件差异。
5. 点击“通过审查”归档通过结果；或者填写非空返工意见并点击“提交返工”，创建新的执行轮次。历史轮次保留可查。

## 状态与操作

| 状态 | 含义 | 可用操作 |
|---|---|---|
| 待办 | 尚未提交执行，或人工解除阻塞 | 编辑、排序、执行、阻塞 |
| 排队 | Host 已接受，等待线程和执行额度 | 查看排队原因、取消排队 |
| 执行中 | 本次执行正在运行 | 查看日志、处理原生审批、停止 |
| 等待用户 | 执行被审批、计划确认或问题阻塞 | 打开对应原生交互、停止 |
| 待审查 | 本次执行正常结束，证据已固定 | 查看结果、通过、返工 |
| 失败／已停止 | 执行失败、取消或重启后无法恢复 | 查看原因、重试；不可直接通过 |
| 已通过 | 用户已接受指定轮次和差异版本 | 查看审查记录、复制为新任务 |

看板用“待办、执行中、待审查、已通过”四列展示，排队和等待用户并入执行中列；失败、停止和人工阻塞留在待办列并显示原因。线程视图展示相同任务的顺序，不复制任务。拖放只改变待办位置或排序，不能伪造执行、通过或取消。同步阻塞及待审查占住当前线程；异步阻塞保留返回位置并允许后续已提交任务前进。

## 执行与审查规则

- 默认执行使用 Workspace 的原生模型配置；缺少有效模型时显示可操作错误，不静默选择其他提供商。审批与沙箱规则由原生执行组合决定。
- 同一任务同一时间最多有一个未终结轮次。重复点击和网络重试返回同一次提交的结果，不产生第二个 Session 或第二份模型开销。
- 并发额度由 Host 配置。一个线程同时只运行一个任务；后续已提交任务需等待前置任务通过或显式异步让出位置。不同线程在隔离 worktree 中可以使用剩余额度。
- Session 空闲、Todo 全部完成、停止请求已接收，都不能单独证明任务成功。只有所属轮次的正常结束及证据固定完成，才能进入待审查。
- 审查摘要注明实际执行的检查及其退出结果；未执行的检查显示“未运行”。失败检查必须在审查中可见，用户通过时需填写接受原因。模型的成功声明不替代检查证据。
- 差异覆盖本次 worktree 相对执行基线的修改、删除和新增文件；二进制和超出显示限制的文件给出明确提示。审查期间文件发生变化时，禁止通过旧版本，要求刷新证据。
- 返工意见进入新轮次的模型输入并记录在 Session 日志中。默认新建专属 Session，以前一轮产物为基线，携带任务、验收条件和返工意见；历史对话作为可查看的引用，不静默重放其他任务的消息。

## 验收标准

| 编号 | 可观察结果 |
|---|---|
| AC-01 | 创建任务不调用模型；刷新后描述、验收条件、线程和位置恢复。 |
| AC-02 | 提交一次任务得到唯一轮次和专属 Session；双击、超时重试不会重复执行。 |
| AC-03 | 缺少模型、非 Git 工作区或创建 worktree 失败时，不显示虚假的执行中状态。 |
| AC-04 | 单线程顺序、跨线程并发额度和同步／异步阻塞均由 Host 强制执行。 |
| AC-05 | 关闭窗口后执行继续；重开能恢复真实进度，断线时显示连接状态而非失败结论。 |
| AC-06 | 实时 Todo、工具活动、审批与问题入口来自原生 Session；没有 Todo 时不显示估算百分比。 |
| AC-07 | 停止只针对当前轮次，等待执行资源结束后显示已停止；旧轮次的迟到事件无效。 |
| AC-08 | 正常结束才进入待审查；失败、取消和恢复不确定状态均不能通过。 |
| AC-09 | 审查可查看执行摘要、检查证据和包含新增文件的差异，并能打开完整日志。 |
| AC-10 | 用户通过的轮次、差异版本、时间及必要的接受原因持久化；通过不提交、不推送、不合并。 |
| AC-11 | 非空返工意见形成新轮次的已记录模型输入；上一轮的结果和审查记录仍可查看。 |
| AC-12 | 多客户端写入冲突拒绝过期版本并提示刷新；SOP 同步不会覆盖执行及审查字段。 |
| AC-13 | Host 重启按持久记录核对执行；无法证明仍在运行的轮次标为中断，不重复发送输入。 |
| AC-14 | 桌面保留缩放和全屏；小屏使用单列和详情抽屉；键盘可完成创建、执行和审查。 |
| AC-15 | 原型明确标注模拟数据；正式验收使用真实组合与可重放模型流程，不能用模拟按钮代替。 |

## 原型评审路径

打开[原型](../../../../packages/client/ui-work-scheduler/prototype/agent-delivery.html)，选择待办任务并执行，使用“推进演示”观察进度和待审查状态，切换“文件差异”，提交返工后再次推进，最后通过审查。另行演示停止、模拟失败、等待审批、断线和线程视图。原型不访问模型或文件系统，不代表这些能力已经实现。
