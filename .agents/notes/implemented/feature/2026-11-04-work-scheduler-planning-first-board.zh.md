# Agent Note: 规划优先的工作调度看板

Status: implemented

[English](2026-11-04-work-scheduler-planning-first-board.md) | 中文

## 问题

浮层把个人任务映射到 Host 执行／审查列。`resolveBoardDrop` 在目标为已通过或待审查时，要求最新轮次已处于待审查，而拖动不能生成证据。用户勾选从未执行的工作时会看到「先完成执行并检查本轮证据，才能通过审查。」，个人看板因此必须先有 worktree 才能把卡片移出待办。

[按 Workspace 持久化的调度器](2026-08-18-web-work-scheduler.zh.md)仍然拥有持久化、SOP 隔离，以及看板不进入模型上下文。[原生执行提案](../../proposed/feature/2026-09-08-work-scheduler-agent-delivery.zh.md)仍然拥有 Host 执行轮次和绑定版本的审查。二者都不把执行证据当作个人规划的前提。

## 决策

浮层默认使用规划看板：待办、用户命名的线程列、已暂停和已完成。没有执行轮次的卡片通过 `moveTask` 和 `archiveTask` 移动，并且不会创建 Host 执行轮次。看板选项提供可选的执行看板（待办／进行中／待审查／已通过）供 SOP 审查。在该板上，尚未执行的卡片仍可不带证据地归档；已有执行记录的卡片继续受证据约束。截图中的文案仅在已有执行记录的卡片被拖到已通过且尚无审查证据时出现。待审查仍由 Host 拥有：把尚未执行的卡片拖到该列会被拒绝，并提示使用已通过或已完成。

「新建任务」和每列的「添加」打开内联编辑器，看板保持可见。验收条件可选。尚未执行的卡片提供「编辑」（看板上就地改写）和「删除」（确认后 `removeTask`）；save 仍禁止改写 Host 执行记录，因此删除不会动这些轮次。已有执行记录的卡片在规划看板上不可拖动，也不显示这两项操作。详情仍通过「执行任务」确认原生执行。

「清空看板」是标题栏可见操作。RiskConfirmation 之后，它通过现有 `workScheduler.save` 路径保存 `createSchedulerState(document.revision)`。Host 存储把版本兼容的空文档视为完整替换该 Workspace 记录，包括 Host 拥有的执行轮次。其他工作区不受影响。面板不会手工删除 SQLite 行。

插件 store 保存打开状态、视图、所选任务和工作区。文档仍在 `WorkSchedulerRuntime`。看板不会进入模型请求或 Session 日志。

## 曾考虑的替代方案

**保留状态看板为默认，并允许不带执行轮次地勾选完成。** 这同样能解除个人任务阻塞，执行看板也实现了该路径。用户首先落到执行列才会出现截图中的横幅，因此常规路径是规划看板，SOP 审查保持为显式高级模式。

**删除 SQLite 领域行以重置。** Host 的 load/save 路径是唯一受支持的重置方式；禁止手工删除存储。

**把看板放入模型上下文，让 agent 勾选任务。** 被现有调度器决策否决：规划状态不得进入 Session 历史。

## 后果

个人规划不再需要 worktree 证据。SOP 审查仍可在可选执行看板和任务详情中使用。组件测试固定默认规划看板、尚未执行的归档不出现证据横幅、已执行且仍在进行中的卡片拖到已通过仍显示该文案、卡片编辑／删除、列内添加，以及「清空看板」只替换一个 Workspace 文档。无密钥 Web SOP 场景在可见的规划看板上创建个人任务，不带执行轮次地归档，并仍能从详情进入执行确认。`WorkScheduler.tsx` 留在 GUI 覆盖豁免中，直到浏览器级测试覆盖浮层、键盘和工作区隔离分支；`board-drop.ts`、`scheduler.ts` 和存储仍按文件设门。
