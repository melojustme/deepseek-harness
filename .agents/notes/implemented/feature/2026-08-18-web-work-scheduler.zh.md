# Agent Note：浏览器本地工作调度板

Status: implemented

[English](2026-08-18-web-work-scheduler.md) | 中文

## 问题

个人调度需要在 dsh Web 中获得持久位置，同时不能把人的规划状态变成模型上下文或 Session 历史。给定原型把独立工作流表示为有序线程，并区分两类阻塞：同步阻塞会暂停一条线程的后续工作，异步阻塞会释放该线程并保留任务返回位置。

## 决策

`@deepseek-ai/dsh-client-ui-work-scheduler` 是纯浏览器插件。它向 `sidebar.footer.action` 贡献入口，向 `shell.overlay` 贡献全屏面板，两个条目通过同一个插件 store 共享打开状态和调度文档。该方案使用已声明的 UI 扩展点，不改变会话所有者或 agent loop。

调度转换是针对带版本 JSON 文档的纯函数。每个任务只能位于一个线程、待分配列表、阻塞列表或归档中。任务转为异步阻塞时记录原线程或待分配索引；唤醒时，如果原线程仍存在，就恢复到该位置。导入规范化会先移除重复和悬空位置，再按状态安置尚未放置的任务。

浏览器把文档保存在 localStorage。调度状态不会进入 Session 日志，因为它不会到达模型请求，也不描述 agent 执行。导入导出提供显式迁移能力，无需增加 Host API 或存储服务。

## 曾考虑的替代方案

没有用 iframe 嵌入独立 HTML，因为这会重复 dsh 的主题、交互与持久化行为，并绕过客户端插件卸载。没有替换会话 slot，因为调度是独立的人用视图，不是 Session 渲染模式。Host 持久化暂缓，因为目前没有跨设备或 Workspace 级消费方。

## 后果

随附 Web profile 从侧栏提供调度入口，并通过 dsh 设计 token 支持浅色、深色、桌面和窄屏布局。领域测试固定阻塞、唤醒、归档和导入规范化行为。状态仍属于单个浏览器配置文件，对 Session、工作流、后台作业和子 agent 没有控制权。
